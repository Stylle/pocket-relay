# 随手传 · Pocket Relay

一个只给自己发消息的轻量网页。电脑发，手机取；支持文字、表情、图片、动图、视频和任意文件。

## Docker Compose 部署

**公共镜像：`stylle/pocket-relay:latest`，支持 amd64 / arm64，无需登录镜像仓库。**

1. 准备 Docker 和 Compose，无需镜像仓库登录。
2. 在 NAS 的 Docker / Compose 管理界面新建项目，粘贴下面的 YAML 并启动。不同 NAS 的入口名称可能不同；如果要求上传文件，使用 [docker-compose.yml](../docker-compose.yml)。**纯镜像部署，不需要下载源码或设置构建目录。**
3. 打开 `http://NAS的IP:28182`，填写账户名并绑定验证器。**第一次初始化在可信内网完成，第一个完成绑定的账户为永久管理员。**

```yaml
services:
  pocket-relay:
    image: stylle/pocket-relay:latest # 必须保留；公共镜像，无需登录
    container_name: pocket-relay             # 可省略，也可改名
    restart: always                         # 建议保留，恢复备份时需要重启
    ports:
      - "28182:8080"                        # 左侧访问端口可改，右侧 8080 不改
    volumes:
      - relay-data:/data                    # 必须保留，用于持久化全部站点数据

volumes:
  relay-data:                               # 上面的命名卷需要此声明
```

**无需任何环境变量，没有 `.env`、初始密码或 setup-token。**账户、存储和公开注册都在网页内设置。命名卷由 Docker 管理权限，推荐直接使用；删除或重建容器不会删除此卷，但不要勾选删除数据卷，也不要执行 `docker compose down -v`。

### 希望数据放在指定 NAS 文件夹

使用 [docker-compose.nas.yml](../docker-compose.nas.yml)，示例如下。路径按你的 NAS 修改，容器内的 `/data` 不改。此写法用宿主机文件夹，不需要末尾的顶层 `volumes` 声明。

```yaml
services:
  pocket-relay:
    image: stylle/pocket-relay:latest
    container_name: pocket-relay
    restart: always
    ports:
      - "28182:8080"
    volumes:
      - /srv/pocket-relay/data:/data # 改为实际数据目录
```

v0.2.0 起，容器先自动初始化专用 data 目录的所有者与权限，然后降权，以 **UID/GID `10001:10001`** 运行服务；普通的 NAS 本地文件夹挂载不再要求手动 chown、PUID/PGID 或 Compose `user: 0`。升级时保留原挂载，移除之前临时添加的 `user` 配置即可。

**必须挂载本项目专用目录，不能挂载共享资料库或系统目录。**初始化会调整该目录及其文件的所有者，目录权限 700、文件 600；遇到符号链接、硬链接、嵌套挂载或特殊文件时拒绝处理，避免改动外部数据。宿主机强制只读、NAS ACL、SELinux 或 NFS root-squash 仍需由宿主机授权，容器不能绕过这些限制。显式指定非 root `user` 时跳过自动初始化，由该用户自行保证目录可写；不需要 Docker socket、特权模式或 777 权限。

### 使用 SSH / 命令行部署

把 [docker-compose.yml](../docker-compose.yml) 保存到 NAS 项目文件夹，在该文件夹中执行：

```bash
docker compose -f docker-compose.yml up -d
```

[compose.yml](../compose.yml) 是同样的命名卷模板，保留兼容已有部署。**不要把两份文件作为不同项目同时启动**，否则会占用相同端口和容器名。

### 可选：从源码构建

需要自行构建时，先取得代码仓库访问权限并下载完整源码，在源码目录执行：

```bash
docker compose -f compose.build.yml up -d --build
```

这不是 NAS 粘贴 YAML 的必需步骤；仅使用上面的现成镜像模板即可部署。

## 使用

本次更新使用 `latest` 或固定 `v0.4.1`；`v0.4.0` 是已取消构建的预发布标签，不作为部署版本。当前运行版本可查看 `/api/status` 中的 `version`。

- 登录后默认进入「本次消息」，只显示该次登录之后的消息；同一标签页刷新不会重置时间起点。历史仍然保存，点击「全部信息」查看，文件页也可查看历史附件。
- 搜索只在「全部信息」显示，「本次消息」和「文件与影像」不显示搜索栏。文本搜索查询本账户的全部历史，不限于已加载消息；可选今天、最近 7/30 天或自定义起止时间（开始包含，结束不包含）。每页最多 100 条，可继续加载；不匹配附件内文。
- 图片为小缩略图和小文件名，点击缩略图查看原图；后台关闭默认加载图片时显示占位图，点击后再加载。视频保持 `preload=none`，不自动加载正文或播放。
- 发送时可选「隐私」，纯文字、纯图片或附件均适用。点消息本身展开，刷新恢复隐藏；展开前不返回完整文字、不请求图片预览，也不会识别并触发链接、邮箱或电话。可用小号「收起」再次隐藏，不再使用大按钮。
- 消息操作栏可「设为隐私 / 取消隐私」，状态保存到 data，并在其他设备轮询时同步；隐私修改会清除其他设备的临时展开缓存。旧下载票据会失效；同账户主动重新下载仍允许。**这是防旁观的显示功能，不是密码加密或端到端加密，文件名仍可见，不加密附件和数据库内容。已经下载或截取的内容无法撤回。**
- HTTP/HTTPS、www 网址使用新标签页打开；邮箱通过 `mailto:` 打开系统邮件应用，常见手机号/格式化电话号码通过 `tel:` 打开拨号应用，实际处理取决于设备。消息 HTML 不会执行，危险协议不转为链接，复制保持原文。内置浏览器会提供转到浏览器的提示，但网页不能强制所有应用打开外部浏览器。
- 手机输入框默认单行，输入时向上增长；移除内置表情选择按钮，仍可用系统键盘输入表情。后台「消息字号」可选小/中/大，存储于服务端，所有设备沿用，默认中。

- 首次输入账户名，用 Google Authenticator 或其他支持标准 TOTP 的验证器扫码，也能手动添加密钥。**密钥只在绑定时展示，请备份验证器。腾讯验证器需确认支持添加标准 TOTP 账户；不是 QQ 专用动态令牌。**
- 登录可勾选「记住登录状态（7 天）」，默认不勾选。勾选后期限从登录时算起，固定 7 天、不因访问延长；重新打开页面、浏览器和正常重启服务均可恢复，不受后台空闲超时影响。临时账户期限更短时以账户期限为准，主动退出立即撤销该浏览器的记住状态及关联会话。
- 长期凭据存于 HttpOnly、SameSite=Strict Cookie，服务端 data 内仅保存哈希；普通网页脚本无法读取 Cookie，不使用 localStorage 保存凭据。公网必须使用 HTTPS；同一站点请保持访问地址一致，清除 Cookie、隐私窗口关闭或切换地址后需重新验证。不要在公用设备上勾选。
- 未勾选时保持原规则：仅同一标签页刷新恢复登录，重新打开页面需验证，默认无操作 15 分钟退出；后台可配置分钟、天或不因空闲退出。网页无法完全识别浏览器的会话恢复行为；服务重启后未记住的会话失效。后台轮询不会续期。
- 每账户最多 32 个记住状态、全站最多 2048 个，超出时撤销最早创建的状态；运行中每账户最多 64 个会话、全站最多 10000 个。网站导出的备份不包含记住状态，恢复备份后需要验证；直接复制整个 data 则包含状态，请保护备份。一个验证码只能用一次，多设备登录请等待下一组，设备需同步时间。
- 各设备登录同一个账户即可看到同一收件箱。不同账户不能互相查看消息、文件；管理员备份包含整个站点数据。
- 默认关闭公开注册。后台开启后，新账户默认有效 1 小时，可调整新账户有效期，也可延长已有临时账户。到期只停止访问，不自动删除永久消息。
- 文件可多选排队、拖放或粘贴剪贴板图片；`Ctrl/⌘ + Enter` 发送。支持复制文字、复制图片和下载；复制图片需要 HTTPS 或 localhost，以及浏览器支持。GIF 复制为静态首帧，下载保留动图。
- 默认永久保留；发送时可选 1 小时、1 天、7 天、30 天或自定义分钟数。到期立即停止访问，后台约一分钟清理附件；远程删除失败会重试。SSD/远程存储上的删除不等于物理安全擦除。
- 默认单文件 256 MB、每账户 5 GB，后台可修改。每次最多 4 个并发上传/远程读取任务；文件落盘传输，不整份加载到服务内存。
- 消息每 4 秒同步一次（页面可见时）。设备名手动设置，浏览器不能读取系统用户名。来源 IP 默认脱敏，反代环境显示代理的脱敏 IP，不信任客户端提供的 `X-Forwarded-For`。

## 存储与备份

后台选择本地、WebDAV 或 SMB。远程存储先通过读写测试才能保存，再选择为默认位置。切换只影响新文件；旧存储配置保留给旧附件使用。WebDAV 填完整服务地址和可选子目录；SMB 填主机 IP/名称、账户和 `共享名/子目录`，使用 TCP 445，仅建议在可信内网或 VPN 中使用。镜像内置 rclone，仅 SMB 操作时启动，无常驻副进程。

所有元数据和加密密钥在 `/data`；远程密码、TOTP 密钥使用 AES-256-GCM 加密保存。**master.key 与数据库同卷保存，因此不能防止拿到整个 data 的人解密；这不是端到端加密。**本地附件不做内容加密，请保护宿主机、NAS 权限并用 HTTPS 访问。

后台可下载密码加密 `.prb` 备份，包含数据库、密钥、所有用户数据和本地附件。远程附件仅备份连接配置及索引，**远程文件本体需另行备份**。备份密码至少 12 字符，丢失无法恢复。格式使用 PBKDF2-SHA256（600,000 次）和分块 AES-GCM，校验篡改、截断及本地附件 SHA-256。

恢复前先验证备份，重启时替换数据；旧数据留在 `/data/previous-*`，确认恢复无误后自行清理。Docker 必须保留 `restart: always`。单份恢复上限 20 GB，需要足够临时磁盘空间。浏览器支持文件流保存时备份直接落盘，否则下载会占用浏览器内存；大量数据也可停容器后直接备份整个 data 卷。远程文件预览/下载暂存到磁盘以支持视频拖动，完成后清理。

## Telegram 机器人

默认关闭；无需新增部署参数、公网域名或回调端口。使用官方 Bot API 长轮询，服务需要能通过 HTTPS 连接 `api.telegram.org`。一个专用机器人绑定一个站内账户和一个 Telegram 私聊；不接收群聊、频道、其他私聊或机器人发出的消息。

1. 在 Telegram 找官方 [@BotFather](https://t.me/BotFather)，用 `/newbot` 创建专用机器人，取得 Token。不要把 Token 放进公开仓库、截图或聊天求助内容。
2. 在网站「管理后台 → Telegram 机器人」填写 Token。先在 Telegram 私聊自己的机器人发送 `/start`，再点击「检测连接 / 识别私聊 ID」。多个 ID 时请核对选择，也可手动填写正整数 Chat ID；运行期间仅显示已绑定 ID，改绑先关闭同步。
3. 选择消息归属账户，分别选择「接收 TG 消息到网站」「网站新消息发送到 TG」，勾选总开关并保存。无需重启容器。公开注册用户不能修改此配置，归属账户到期会停止同步。
4. 状态区域显示最近收发时间、待发/失败数量及错误；前端每 10 秒更新。网络异常自动重试，发送连续失败 10 次后暂停该条，可点击「重试失败发送」。一个机器人只能由一个实例接收；已有 Webhook 或其他长轮询实例会提示冲突，不会擅自删除别的应用的 Webhook。

接收文字、照片、视频、音频、文件与贴纸附件。可预览格式由浏览器决定，不支持预览的格式仍可下载。收到的信息写入归属账户当前选定的本地/WebDAV/SMB 存储，默认永久保留，并按 Telegram update ID 去重；其他聊天不会写入站点。仅接收开启后产生的信息，不会把网站已有历史批量发到 Telegram，也不会把 TG 收到的消息再次回发形成循环。

官方云端接口目前接收附件最多 **20 MB**、发送附件最多 **50 MB**，还受站点单文件上限和账户配额约束；超限用文字提示，不影响网页原本的大文件传输。网页发送的附件作为原始文件发送到 TG，长文字自动分段。限制以 [Telegram Bot API](https://core.telegram.org/bots/api#getfile) 为准，本项目不部署额外的本地 Bot API 服务。

**开启发送意味着把该账户的新消息交给 Telegram 保存。**隐私遮挡消息默认不转发，只有显式开启对应选项后才会转发完整正文与附件；网页删除、到期、退出或重新遮挡都不会删除 Telegram 副本。机器人聊天不是端到端加密，不适合无法接受第三方保存的资料。

「收到的 TG 消息默认设为隐私」初始开启，可在后台关闭，影响以后接收的文字与附件，不修改历史。已发消息改为隐私时取消该消息尚未处理的发送队列，不补发取消隐私的历史消息；正在发送或已送达的副本无法保证撤回。

Token 使用站点密钥加密保存在 data 数据库，网页不会回传已存 Token；留空保存表示保留原 Token。修改机器人配置或关闭同步会取消在途请求并清空旧发送队列，已被 Telegram 接收的消息无法撤回。普通容器重启保留发送队列与分段进度；极端情况下 Telegram 已收件但响应丢失，重试可能产生重复消息，不保证跨系统恰好一次投递。

整站备份包含机器人加密配置、接收进度与发送队列。恢复前停止旧实例，避免同一机器人被两个站点同时运行。网络需要代理时可自行使用 Docker 标准 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量，不是部署必填项。

## 微信

当前版本不直接登录个人微信，也未接入企业微信消息回调。个人微信非官方机器人存在账号风险；普通企业微信群 Webhook 主要用于发往群聊，不能当作接收任意私人微信消息的接口。后续可做独立的官方企微回调适配器，不影响站点登录和数据隔离。

## 更新与开发

```bash
docker compose -f docker-compose.yml pull
docker compose -f docker-compose.yml up -d
```

NAS 图形界面部署则更新镜像并重新创建原项目，保留原数据卷或文件夹挂载。若使用 `compose.yml` 或 `docker-compose.nas.yml`，命令中的文件名对应替换即可。

Go 1.26+，无前端构建步骤：`go test ./... && go vet ./... && go run .`。非 Docker 默认数据目录 `./data`；可选 `DATA_DIR`、`LISTEN_ADDR`，默认端口 8080。没有其他必填变量。

GitHub Actions 执行自动测试、真实 SMB 回环测试、Docker 启动/重启测试，再发布多架构 GHCR 镜像。新仓库如配置 `DOCKERHUB_USERNAME` 和 `DOCKERHUB_TOKEN` Secrets，推送 `v*` 标签时额外发布 Docker Hub。
